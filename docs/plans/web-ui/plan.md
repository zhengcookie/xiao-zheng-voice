# Web UI 界面 — 自由形式计划

> 创建时间：2025-09-14

## 问题描述

当前项目只有命令行脚本和 README，用户需要手动配置环境、准备音频数据、运行训练脚本、再用代码合成语音。整个流程门槛高，不适合非技术用户。需要一个 Web 界面让用户通过浏览器完成声音克隆的全流程。

**受影响的用户**：想要克隆身边人声音的个人用户，可能没有深度学习或命令行经验。

## 初步想法

### 核心流程（三步走）

1. **上传音频** → 用户上传目标人物的语音样本（支持拖拽、多文件）
2. **训练模型** → 一键启动训练，显示实时进度和日志
3. **合成语音** → 输入文本，选择已训练的声音模型，生成并播放/下载音频

### 技术选型考虑

- **后端**: Python (FastAPI / Gradio / Streamlit)
  - GPT-SoVITS、RVC 等参考项目都用 Python，保持生态一致
  - Gradio 上手最快，但定制性差；FastAPI 更灵活
- **前端**: React / Vue / 纯 HTML
  - 如果用 Gradio，前端自动生成，不需要额外写
  - 如果用 FastAPI，需要自己写前端
- **模型推理**: 本地 GPU 推理（不做云端部署）

### 功能模块

| 模块 | 功能 | 优先级 |
|------|------|--------|
| 音频上传 | 拖拽上传、格式校验、波形预览 | P0 |
| 音频预处理 | 自动降噪、分割、标注 | P1 |
| 模型训练 | 一键训练、进度条、日志输出 | P0 |
| 语音合成 | 文本输入、模型选择、生成播放 | P0 |
| 模型管理 | 查看已训练模型、删除、重命名 | P1 |
| 音频播放器 | 播放生成的音频、下载 | P0 |

## 约束条件

- **硬件**: 用户本地有 GPU（≥8GB 显存），做本地推理
- **非商业**: 仅学习和个人使用，不做用户认证/权限系统
- **单一用户**: 本地部署，单用户使用，不需要多租户
- **参考项目**: 以 GPT-SoVITS 为主要后端（最成熟、中文支持最好）

## 不确定的地方

1. **Gradio vs FastAPI** — Gradio 开发快但 UI 定制性差；FastAPI 灵活但工作量大。需要权衡。
2. **音频预处理的范围** — 是否需要自动降噪/分割？还是让用户自己准备好再上传？
3. **训练过程** — 是在 Web UI 中启动子进程，还是用队列系统？
4. **多模型支持** — 第一版只支持 GPT-SoVITS，还是预留 RVC/CosyVoice 的扩展接口？
