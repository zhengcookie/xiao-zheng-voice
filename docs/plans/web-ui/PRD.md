# Web UI 界面 — PRD

> 创建时间：2025-09-14
> 状态：Draft

## 问题陈述

用户想要克隆身边人的声音，但当前项目只有命令行工具，操作门槛高。需要一个直观的 Web 界面，让用户通过浏览器完成「上传音频 → 训练模型 → 合成语音」的完整流程。

## 解决方案描述

基于 Gradio 构建单页 Web 应用，后端调用 GPT-SoVITS 进行模型训练和语音合成。选择 Gradio 是因为：(1) 与 GPT-SoVITS 生态一致，(2) 自动生成响应式 UI，(3) 内置音频播放器和文件上传组件，(4) 开发速度最快。应用以本地单用户模式运行，通过 `python app.py` 启动。

## 用户故事

### US-1: 上传音频样本

**作为** 想要克隆声音的用户
**我想要** 上传目标人物的语音文件
**以便** 系统可以用这些音频训练声音模型

**验收标准**:
- Given 用户在首页，When 拖拽一个 .wav/.mp3/.flac 文件到上传区域，Then 文件被接收并显示文件名和时长
- Given 用户在首页，When 点击上传按钮选择文件，Then 文件选择对话框打开，选中后文件被接收
- Given 用户上传了文件，When 文件格式不在支持列表中，Then 显示错误提示「仅支持 WAV/MP3/FLAC 格式」
- Given 用户上传了文件，When 文件时长小于 3 秒，Then 显示警告「音频过短，建议至少 10 秒」
- Given 用户上传了多个文件，When 上传完成，Then 显示文件列表，包含文件名、时长、大小

**边缘情况**:
- 文件大小超过 500MB 时拒绝并提示
- 网络中断导致上传失败时显示重试按钮
- 上传同名文件时覆盖旧文件

### US-2: 训练声音模型

**作为** 已上传音频的用户
**我想要** 一键启动模型训练
**以便** 获得可以合成该声音的模型

**验收标准**:
- Given 用户已上传音频，When 点击「开始训练」按钮，Then 训练任务启动，按钮变为「训练中...」并禁用
- Given 训练正在进行，When 用户查看页面，Then 显示实时进度条（百分比）和滚动日志
- Given 训练正在进行，When 用户点击「取消训练」，Then 训练中断，资源释放，状态回到初始
- Given 训练完成，When 用户查看页面，Then 显示「训练完成」状态，模型自动出现在模型列表中
- Given 没有上传音频，When 用户点击「开始训练」，Then 按钮禁用，提示「请先上传音频」

**边缘情况**:
- GPU 显存不足时在启动前检测并提示「显存不足，无法训练」
- 训练过程中 GPU 被其他进程占用导致 OOM，捕获错误并提示用户
- 训练进程意外崩溃，检测退出码并显示错误日志

### US-3: 合成语音

**作为** 已训练模型的用户
**我想要** 输入文本并用克隆的声音朗读
**以便** 获得目标声音的语音文件

**验收标准**:
- Given 用户在合成页面，When 输入中文文本并选择模型，Then 「合成」按钮激活
- Given 用户点击「合成」，When 合成完成，Then 页面显示音频播放器，自动播放生成的语音
- Given 合成完成，When 用户点击「下载」，Then 浏览器下载 .wav 文件
- Given 文本超过 500 字，When 用户点击合成，Then 显示警告「文本较长，合成可能需要更长时间」
- Given 没有已训练模型，When 用户进入合成页面，Then 显示提示「请先训练模型」

**边缘情况**:
- 合成过程中用户刷新页面，任务继续在后台运行
- 生成的音频质量差（如杂音、语速异常）时提供参数调整选项

### US-4: 模型管理

**作为** 有多个已训练模型的用户
**我想要** 查看、重命名和删除模型
**以便** 管理我的声音模型库

**验收标准**:
- Given 用户在模型列表页，When 页面加载，Then 显示所有已训练模型，包含名称、训练时间、文件大小
- Given 用户点击模型名称，When 处于编辑模式，Then 名称变为可编辑输入框，支持修改后保存
- Given 用户点击删除按钮，When 确认对话框中点击「确认」，Then 模型文件被删除，列表更新
- Given 用户点击删除按钮，When 确认对话框中点击「取消」，Then 无操作

## 实现决策

### 技术栈

| 层 | 选择 | 理由 |
|----|------|------|
| Web 框架 | Gradio 4.x | 与 GPT-SoVITS 生态一致，自带 UI 组件 |
| 后端语言 | Python 3.10+ | 与 ML 生态一致 |
| 模型后端 | GPT-SoVITS | 中文支持最好，社区最活跃 |
| 音频处理 | librosa + pydub | 音频格式转换和预处理 |
| 进程管理 | subprocess + threading | 训练任务在子进程中运行 |

### 模块设计

```
app.py                  ← Gradio UI 入口
├── uploader.py         ← 音频上传与预处理逻辑
├── trainer.py          ← 模型训练封装（调用 GPT-SoVITS）
├── synthesizer.py      ← 语音合成封装
├── model_manager.py    ← 模型文件管理
└── utils.py            ← 音频格式转换、文件操作等工具函数
```

### 接口变更

无外部 API — 所有操作通过 Gradio 组件的事件回调在本地完成。

内部模块接口：
- `uploader.process_audio(file_path) -> (processed_path, metadata)`
- `trainer.start_training(audio_dir, config) -> TrainingHandle`
- `trainer.get_status(handle) -> (progress, logs, status)`
- `synthesizer.generate(text, model_path) -> audio_path`
- `model_manager.list_models() -> [ModelInfo]`
- `model_manager.delete_model(name) -> bool`

### 数据模型

不需要数据库。文件系统即数据存储：

```
workspace/
├── uploads/              ← 用户上传的原始音频
├── processed/            ← 预处理后的音频
├── models/               ← 训练好的模型文件
│   └── {model_name}/
│       ├── config.json   ← 模型元数据
│       └── *.pth         ← 模型权重
└── outputs/              ← 合成的音频文件
```

### 模式变更

- 单进程 Gradio 应用，通过子进程隔离训练任务
- 文件系统存储，无数据库依赖
- 本地运行，无网络依赖
